Asunto: Publicar en un servidor el sistema de inventario físico vs SAP (ingreso con Entra ID)

Hola,

Les escribo para pedirles que publiquen en un servidor interno una aplicación que desarrollamos para conciliar el inventario físico de Farmacia contra SAP. Hoy funciona, pero cada uno la abre en su computadora y las decisiones quedan ahí: necesitamos que esté disponible para todos y que el ingreso sea con la cuenta corporativa.

De qué se trata, en tres líneas

Las bases de San Juan, Neuquén y Salta contaron lo que hay en el depósito; SAP tiene registrado lo que debería haber. Los dos listados nombran los mismos productos de maneras distintas, así que el sistema establece la correspondencia producto por producto y deja 1.991 casos para decidir. No se conecta a SAP ni lo modifica: lo que produce es el pedido de trabajo —qué dar de alta, qué dar de baja, qué ajustar— con el nombre de quién decidió cada cosa.

Cómo se usa

Es una página web. Se entra, se elige una base o las tres, y cada caso aparece como una pregunta concreta con lo que dice el depósito de un lado y lo que dice SAP del otro; se contesta con un clic, de a uno o en lote. Al final, la pantalla «Aplicar en SAP» resume qué hay que hacer con cada decisión, y todo se puede bajar en Excel. El manual adjunto lo explica entero.

Lo que necesitamos de ustedes

  1. Un servidor Linux chico con Node 22.5 o superior. No hay base de datos externa ni dependencias que instalar: la aplicación usa sólo lo que viene con Node y guarda en un archivo SQLite en disco, con respaldo diario automático.
  2. Un nombre DNS interno con HTTPS, por ejemplo inventario.emergencias.com.ar. Puede ir detrás del proxy que ya usen.
  3. Un registro de aplicación en Microsoft Entra ID, que es lo que permite entrar con las credenciales corporativas:
    • tipo de cuenta: sólo este inquilino;
    • plataforma Web (no SPA: el secreto queda en el servidor, el navegador nunca ve un token de Microsoft);
    • URI de redirección: https://<el nombre que elijan>/auth/callback;
    • y pasarnos Id. de aplicación, Id. de directorio y un secreto de cliente.
    Los permisos que Azure agrega por defecto alcanzan: no hace falta consentimiento de administrador ni ningún permiso adicional.
  4. Dejarla restringida a @emergencias.com.ar. La aplicación ya valida el dominio y rechaza invitados, además de lo que configuren ustedes.

El paquete adjunto trae todo: el servicio para systemd, un Dockerfile por si prefieren contenedor, el archivo de configuración de ejemplo y el instructivo paso a paso (EMPEZAR-ACA.md). De configuración, obligatorias son cuatro variables —las tres del registro de Azure más la URI de redirección—; el resto tiene valores por defecto y está comentado en el archivo de ejemplo. Si quieren verla andar antes de registrar nada en Azure, arranca sin login con un solo comando, escuchando sólo en localhost.

Datos que maneja: el inventario de Farmacia y el stock de SAP de las tres bases, más las decisiones que se van tomando. Sin datos personales más allá del nombre de quien decide, que es justamente el punto.

Adjunto el paquete de instalación y el manual. Quedo a disposición para lo que haga falta, y si prefieren una llamada corta para verlo juntos, cuando les quede cómodo.
